## Estructura objetivo (sin cambios drásticos)
src/
├── app/        # RUTAS Y API (NO TOCAR) - Páginas, layouts, route handlers en app/api/
├── ui/         # FRONTEND PURO - Componentes genéricos/reutilizables (botones, inputs, modales, navbar, footer)
├── features/   # FRONTEND POR DOMINIO - Componentes agrupados por funcionalidad (noticias, equipo, galería, tienda, calendario)
├── server/     # BACKEND PURO - Lógica server-only (auth, supabase server/admin, r2, rateLimit, validaciones server)
├── shared/     # COMPARTIDO - Tipos, schemas zod, constantes, helpers seguros para cliente+servidor
├── data/       # DATOS ESTÁTICOS - Se mantiene tal como está
└── middleware.ts

## ¿Qué va dónde?
- ui/        -> Solo presentación. NO usar cookies(), headers(), process.env secretos, ni cliente Supabase admin/server
- features/  -> UI + lógica de cliente ligada a un dominio específico
- server/    -> ÚNICAMENTE server-only. Si usa cookies/headers o claves privadas -> server/
- shared/    -> Tipos/constantes/validaciones seguras compartidas
- app/       -> SIEMPRE intacto. Las rutas no se mueven

## Reglas para seguir desde hoy
1. Antes de mover algo: clasificar (frontend/backend/compartido)
2. Mover por LOTES pequeños (1-5 archivos) y actualizar imports inmediatamente
3. Después de cada lote: npx tsc --noEmit (o npm run build si hay dudas)
4. Nunca mover archivos dentro de app/ o app/api/
5. Mantener compatibilidad con imports existentes (@/components/*, @/lib/*) hasta migrar
6. Registrar TODO en CAMBIOS.txt con fecha/hora, archivos, verificación y resultado
